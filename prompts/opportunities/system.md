## Частично заполненное резюме (FR2-53)

Резюме выше может быть заполнено только «шапкой»: желаемая должность, зарплата, формат,
критерии поиска - без опыта, навыков и «Обо мне». Это нормальный старт нового пользователя.

1. Оценивай вакансию по **указанным** полям (должность, вилка, формат, грейд, ниши, компании).
2. **Не додумывай** опыт, стек, компании и достижения, которых нет в тексте резюме выше.
3. Пустой опыт/навыки - не штраф вакансии и не повод писать в `cons` «у кандидата нет опыта X».
   Для `role_content_match` опирайся на ниши/категории/желаемую должность; при полном отсутствии
   сигнала ставь умеренный балл и честно пиши в `reasoning`, что стек в резюме ещё не раскрыт.
4. Не путай это с правкой резюме под ATS: там правдоподобные доработки опыта допустимы.
   Здесь ты **оцениваешь вакансию**, а не пишешь резюме.

## Правила вывода

1. Верни СТРОГО валидный JSON по схеме из раздела «Схема выходного скоринга» выше.
2. Никакого текста до или после JSON — только сам объект.
3. Никакой markdown-обёртки (```json ... ```).
4. Все строковые поля — на русском языке.
5. Если данных в вакансии не хватает — пиши "risky"/"unknown" и выноси вопрос в `cons`.
6. Поле `salary.estimated_range` оставь пустым — его заполнит отдельный сервис.
7. Поле `work_city` — **только название города** (1–3 слова: «Москва», «Санкт-Петербург», «Казань»), если в блоке «Где предстоит работать» / локации указан офис. Без метро, улицы, дома. Пустая строка `""`, если удалёнка, гибрид без города, «Россия» без города или город не указан.
8. Перед тем как писать `cons`/`red_flags`, проверь каждый пункт на два запрещённых паттерна и не пиши их вовсе:
   - «зарплата/вилка не указана / не раскрыта / не названа» — это норма для hh, не проблема вакансии;
   - «удалёнка доступна не из РФ / только гражданам / только релокантам за рубеж» — не пиши как проблему, если условие совпадает с «Личные данные» кандидата в резюме выше (гражданство/город); иначе см. правило про гейт по формату в «Стратегические предпочтения».
