# Frontend

React 19 + Vite + TypeScript + Tailwind 4. Команды сборки/тестов — в корневом `CLAUDE.md`.

## Словарь ролей (D-01)

Тёмной темы не будет (см. корневой `CLAUDE.md`, Решение 2) — токены нужны не для переключения,
а для того, чтобы правка внешнего вида была правкой одного места (`src/styles/globals.css`), а
не 70 файлов. Не полная инвентаризация 978 хардкодов `slate-*`/`bg-white`, а роли, которых
хватает новому коду:

| Роль | Токен/класс | Когда использовать |
| --- | --- | --- |
| Поверхность страницы | `bg-background` | фон раздела под всем контентом |
| Поверхность карточки | `bg-card` (+ `text-card-foreground`, если текст на ней) | вакансия, панель, диалог, любой «приподнятый» блок |
| Приглушённая поверхность | `bg-muted` | вложенный блок внутри карточки (метаданные, неактивный таб, скелет) |
| Граница | `border-border` | разделитель, рамка карточки/инпута — не `border-slate-*` |
| Основной текст | `text-foreground` | заголовки, значения, то, что читают в первую очередь |
| Второстепенный текст | `text-muted-foreground` | подписи полей, метаданные, вспомогательные пояснения |
| Подпись | `text-muted-foreground text-xs` | таймстемпы, счётчики, самый низкий приоритет чтения |

Статусные цвета (`emerald/amber/rose/sky/violet` — рекомендация, формат работы, mastery) — вне
этого словаря, у них отдельные токены `--status-*` (D-04). Новый код и общие примитивы
(`components/ui/**`) пишутся на этих ролях сразу; существующие экраны переводятся попутно, когда
их и так открывают другие шаги (D-02).

## Типографика (D-07)

Шкала — стандартные Tailwind-размеры `text-xs/sm/base/lg` (+ `xl`/`2xl` для крупных цифр —
скор вакансии, ячейки «Рынка», счётчик фильтров), три начертания `font-normal/medium/semibold`.
`font-bold` не используется — там, где он был (скор вакансии, счётчик фильтров, крупный балл
резюме), это тот же `font-semibold` на крупном кегле, отдельного «более жирного» уровня в шкале
нет. Раньше размер выбирался на глаз (`text-[8px]…text-[15px]` — 68 вхождений в 29 файлах, по
факту не рассечка по смыслу, а дрейф пикселей); ниже — роли, которые покрывают все прежние
кейсы:

| Роль | Классы | Где |
| --- | --- | --- |
| Заголовок раздела | `text-xl font-semibold tracking-tight` | `<h1>` раздела — сегодня только «Параметры», задел под `PageHeader` (D-08) |
| Заголовок карточки | `text-sm font-semibold` | название компании/вакансии/оффера в карточке, шапка панели |
| Текст (по умолчанию) | `text-sm` | обычный интерфейсный текст — большая часть UI уже на нём |
| Текст для чтения | `text-base` | там, где текст должен читаться комфортно длинными фразами: сообщения чата, устный питч, форкаст рынка (было `text-[15px]`) |
| Метаданные | `text-xs text-muted-foreground` (`font-medium` — для табличных чисел: даты, счётчики) | второстепенное значение рядом с основным текстом |
| Подпись-ярлык | `text-xs font-medium uppercase tracking-wider text-muted-foreground` | «эйбрау»-ярлык над значением/блоком («Дедлайн ответа», «Ответ», код языка в блоке кода) — не путать с ролью «Подпись» словаря D-01 (та — про цвет таймстемпов/счётчиков, это — про размер+начертание ярлыка) |

Кастомных размеров вне шкалы нет, кроме одного явно маркированного исключения: цифра/буква
внутри значка фиксированного размера (`size-3.5`/`size-4` кружок с номером этапа/приоритетом,
двухбуквенный логотип источника в `SourceIcon`) — это не текст для чтения, а глиф, подогнанный
под контейнер; такие места помечены комментарием `вне шкалы D-07`.

## Сетка и отступы (D-11)

Шкала — Tailwind-юниты `1/2/3/4/6` (`4/8/12/16/24` px). Это про **layout-отступы** (паддинг
раздела, стек блоков, зазор грида) — не про внутрикомпонентные микро-зазоры (иконка+текст в
чипе/бейдже/кнопке: `gap-1.5`, `px-2.5` и т.п. остаются отдельной, более мелкой осью и в эту
шкалу не сводятся, как глифы вне шкалы D-07).

| Роль | Класс | Где |
| --- | --- | --- |
| Паддинг раздела | `p-6` (24) | контентная область каждого раздела реестра (доска, «Рынок», «Параметры», вкладки «Техничек») |
| Стек крупных блоков | `space-y-6` (24) | независимые блоки/карточки на одной странице (пакет скрининга, сетка+«Ситуация» рынка, секции «Параметров», вкладка вопросов «Техничек») |
| Стек внутри блока | `space-y-4` (16) | связанные поля/строки внутри одного блока (скелетон формы; стек карточек-секций `ResumeForm` — они уже разграничены рамкой каждой карточки, поэтому зазор между ними — этот уровень, а не «стек крупных блоков») |
| Плотный грид/ряд | `gap-3` (12) | грид с плотной сеткой мелких полей (`ResumeForm` секции с `dense`: «Личные данные», «Контакты») и повторяемые компактные строки (пункты опыта/образования) |
| Просторный грид | `gap-4` (16) | грид с некомпактной секцией одной темы (`ResumeForm` «Желаемая должность») и колонки доски вакансий |

**Контейнер раздела:** ограничение ширины колонки (`mx-auto max-w-*`) — не универсальное правило,
а сознательный выбор по типу контента. Читаемый/составляемый контент в одну колонку (форма,
композер, длинный текст) ограничивается шириной, иначе строка на 1920 растягивается неудобно для
чтения: `max-w-3xl` (48rem) — одноколоночный композер/чтение (`SettingsPage`, вкладки «вопросы» и
«разбор» и панель «Прогресс» в `TechPage` — все три режима одной страницы теперь на одной ширине,
раньше «разбор» единственный растягивался во всю ширину при переключении вкладки — это и было
реальным дрейфом ритма, который чинит шаг); `max-w-4xl` (56rem) — тот же принцип, но контенту
нужно больше места под свои внутренние 2-3-колоночные грид-секции (`ResumeForm`). Разделы-доски и
рельсы (`JobsPage`/`JobsWorkspace`, `ChatPage`, `OffersPage`, `ScreeningPage`, `MarketPage`)
растягиваются на всю ширину намеренно — канбан-колонки, рельсы карточек и двухпанельные раскладки
выигрывают от места на 1920, а не проигрывают от его отсутствия колонки.

## Движение (D-14)

Токены — `src/styles/globals.css` (`.motion-rise/fade/pop`, `.motion-stagger-0..7`), применяются
через хуки `src/lib/utils.ts`, не вручную. Правило по типу изменения:

| Что происходит | Токен/хук | Пример |
| --- | --- | --- |
| Список показывается впервые | `motion-rise` + каскад `motion-stagger-0..7` (первые 8 элементов) | доска/список вакансий, рельс вакансий/офферов, сетка «Рынка» — все через `useListAppearMotion` |
| Состав списка меняется (фильтр, поиск) | `motion-fade`, без каскада | тот же хук — `mode` переключается на `"fade"` после первого показа |
| Конкретный элемент меняет состояние (не весь список) | `motion-pop` через `usePopMotion` | карточка вакансии, приземлившаяся в другую колонку доски после drag/drop |
| Модальное окно (`Dialog`/`AlertDialog`) | `fade-in-0 zoom-in-95 duration-200` (tw-animate-css, `data-[state=]`) | подтверждение действия, детальный диалог |
| Лёгкий поповер (`Popover`/`DropdownMenu`/`Select`/`Tooltip`) | `fade-in-0 zoom-in-95` без явной длительности (150 мс по умолчанию) | контекстное меню, подсказка |
| Боковая шторка (`Sheet`) | `slide-in-from-right` | дровер вакансии |

Модалки и поповеры не переиспользуют `.motion-pop` буквально: у них есть анимация закрытия
(`data-[state=closed]`), которой у `.motion-rise/fade/pop` нет — те рассчитаны на одноразовое
появление элемента списка через смену React `key`, не на управляемый Radix-примитивами цикл
открыт/закрыт. Здесь «pop» — про характер движения (лёгкое масштабирование), а не про общий CSS-
класс. Обе группы внутри себя уже единообразны (все модалки — 200 мс, все поповеры — 150 мс) —
дальше не сводить в одно: разная длительность разграничивает «требует явного закрытия» и
«транзитный UI поверх контента».

`useListAppearMotion` и `usePopMotion` — единственные точки, где стоит `useState`/`useEffect` для
motion; новый список/точечный эффект добавляет вызов одного из них, а не свой `setTimeout`.

При `prefers-reduced-motion: reduce` анимаций нет ни у токенов (`@media` в `globals.css` делает
классы no-op), ни у Radix-примитивов (`.animate-in`/`.animate-out` от `tw-animate-css` глушатся
тем же файлом — у библиотеки своей проверки reduced-motion нет).

## Deep-link по разделам (F-10)

Единый контракт: **везде, кроме «Вакансий», выбор вакансии — query-параметр `?vacancy=`**.
«Вакансии» — единственное исключение, там путь `/jobs/:vacancyId`, потому что эта форма уже
опубликована в расширении (ссылки из hh.ru/getmatch на конкретную вакансию) — менять её значит
ломать существующую интеграцию без выгоды.

| Раздел | Форма ссылки | Пример |
| --- | --- | --- |
| Вакансии (`/jobs`) | path param `:vacancyId` | `/jobs/hh_123456` |
| Чаты (`/chat`) | `?vacancy=` — диалог по вакансии; `?panel=new` — новая вакансия; `?panel=context:<id>` — контекст | `/chat?vacancy=hh_123456` |
| Скрининги (`/screening`) | `?vacancy=` | `/screening?vacancy=hh_123456` |
| Технички (`/tech`) | `?vacancy=` | `/tech?vacancy=hh_123456` |
| Офферы, Резюме, Рынок, Параметры | без выбора вакансии | — |

Скрининги и Технички дополнительно шарят один ключ sessionStorage (`prep-vacancy`) — переход
между ними без явного `?vacancy=` в ссылке сохраняет последнюю открытую вакансию.

Хранение реализует `usePersistedRouteState` (`src/lib/use-persisted-route-state.ts`): URL —
источник истины и переживает F5; sessionStorage вкладки — фолбэк, пока в URL параметра нет
(например, переход на раздел из сайдбара, без явного выбора). Для «вида»/раскладки экрана
(доска vs список и т.п., не то, чем делятся по ссылке) параметр `param` не передаётся — значение
живёт только в sessionStorage, в URL ему не место.
