# Скрининги (`screening`)

домен бэкенда: `core/domains/preparation`

Self-pres pack: brief, pitch, вопросы HR↔кандидат, легенда.

Правая панель (`QuestionsChatPanel`) живёт в двух состояниях:

- **до скрининга** — подготовка: «Рассказ об опыте» (`PitchScript`) закреплён сверху, ниже вопросы
  пакета как сообщения (`QuestionBubble` из `features/tech/PrepChat`) и счётчик просмотренных;
- **после скрининга** (расшифровка вставлена и разобрана) — `DebriefReview` из
  `features/tech/DebriefSection`: одна оценка в шапке и вкладки «Диалог | Разбор». Пакет, рассказ
  и счётчик скрыты — прогноз перестаёт что-либо значить рядом с реальными вопросами и ответами;
  вернуть их можно кнопкой «Подготовка» в шапке.

Композер снизу переключает «Агент» / «Расшифровка» (у второй — галка, когда транскрипт уже
разобран). Оба режима переиспользуют бэкенд Техничек через `stage="screening"` (`prep_chat` и
`debrief`, см. `core/domains/preparation/models.py::PrepStage`) — вставленная здесь расшифровка
HR-скрининга автоматически видна в Техничках (этап HR-скрининг в ленте `PrepChatThread`), это одна
и та же строка в БД. Общие куски вынесены в `question-cards.ts` (маппинг пакета →
`PrepQuestionOut`) и `use-screening-debrief.ts` (фильтр расшифровок по `stage="screening"`).

Разбор — фоновая задача: после «Анализ» поле сразу очищается, композер возвращается в «Агент», а
прогресс идёт карточкой `DebriefProgress` в ленте (черновая разметка реплик + шаги). Отметка
«расшифровка есть/нет» на карточках рельса — `TranscriptMark` по индексу `useDebriefStageIndex`.
