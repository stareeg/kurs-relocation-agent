# career

Портфолио (достижения), лента событий, долгая память кандидата, режим/трек поиска, дружба.

`timeline` слушает шину (stage/offer/debrief/search_mode/search_track → `career_timeline`) и
пишет ручные события (`api/routers/career/timeline.py`); вставка идемпотентна для `kind="offer"`
по `source_ref` (0152, Этап 1) — повторная публикация `OfferReceived` не дублирует строку.
`VacancyDeduplicated` (дубль вакансии на другой площадке) в ленту больше не пишется — технический
шум, к карьере кандидата отношения не имеет. Название компании/вакансии в `title` не хранится —
резолвится на чтении в `core/app/scenarios/career_timeline_view.py` (`career` не должен знать про
`opportunities.jobs`); транспортная схема с этим обогащением — `TimelineEventView` в
`api/schemas/career.py`. `portfolio` — элементы портфолио из резюме/разборов/офферов
(`api/routers/career/portfolio.py`), тоже идемпотентен по `source_ref` и умеет удалять
(`DELETE /api/career/portfolio/{id}`) — без этого автосоздание карточки по событию (сильный
разбор/зафиксированный оффер, `record_portfolio_from_debrief`/`record_portfolio_from_offer` в
`career/events.py`) было бы билетом в один конец: своего статуса «черновик» у элемента нет,
неверную карточку убирает только удаление. `facts` — долгая память из разборов → prep/chat,
читается/правится/удаляется владельцем (`api/routers/career/facts.py`); повторный разбор с тем
же `fact_type`+`payload.topic` обновляет уже активный факт вместо новой почти дословно
повторяющей строки (мердж по теме, не по тексту — формулировка каждый раз слегка разная).
`search_state` — режим поиска (SearchMode) + журнал переходов (`GET/PATCH
/api/career/search-mode`). `track_state` — набор треков поиска (основная / вторая работа,
`GET/PATCH /api/career/track`). `friendships_repo` — коды дружбы и связи друзей
(`api/routers/career/friendships.py`). **UI дружбы** — не на этом экране: компактный блок в
«Аккаунте» (`frontend/src/features/settings/FriendsCompactSection.tsx`). На «Карьере» друзей
не рендерить «для полноты».

**Граница с треком поиска.** Трек поиска (`SearchTrack`: основная / вторая работа) — форма
занятости, сценарий «остаюсь где есть», не физический переезд.

## Экран «Карьера» (редизайн Э9, `plans/dual_employment_and_contracting_2026.md`)

Раздел долго состоял из четырёх CRUD-форм (цели, skill-таргеты, портфолио, релокация), при
этом два реально ценных актива домена — лента (`career_timeline`) и долгая память
(`career_facts`) — не имели роутеров и были не видны владельцу. Э9.7 удалил Цели/skill-таргеты
(A-23, нигде не подключались в UI) и граф релокации (A-25, владелец подтвердил явное «да») —
вместе с ними ушёл и `career.profile_hints` (единственный потребитель этих моделей, на проде
всегда пустой — создать цель/шаг было негде).

Раскладка экрана — один вертикальный поток без вкладок,
`frontend/src/features/career/CareerPage.tsx`:

| Блок | Источник | Роутер |
| --- | --- | --- |
| Где я сейчас (снапшот) | `core/app/scenarios/career_snapshot.py` | `GET /api/career/snapshot` |
| Что изменилось (дельты за 30 дней, `None` — истории меньше двух точек) | `core/app/scenarios/career_delta.py` | `GET /api/career/delta` |
| Лента | `career/timeline.py` + `app/scenarios/career_timeline_view.py` (обогащение на чтении) | `GET/POST /api/career/timeline` |
| Память | `career/facts.py` | `GET/PATCH/DELETE /api/career/facts` |
| Достижения | `career/portfolio.py` | `GET/POST /api/career/portfolio/*`, `DELETE /api/career/portfolio/{id}` |

«Достижения» — карточка с действием «Копировать» (буфер обмена), не автоматическая инъекция
в промпт `cover_letter`/`screening_pitch`: такого хука в генерации нет, заводить его вслепую
под одну кнопку не входило в этот заход.

**Второй заход (`plans/career_redesign_2026_08_26.md`, Этапы 1-5, сделано):** владелец назвал
экран «полнейший AI slop» на реальных данных — дубли строк, `vacancy_id` вместо названия в
ленте, внутренний enum-жаргон, стена LLM-абзацев без иерархии в «Памяти», три параллельные формы
ручного добавления в «Достижениях» там, где событие уже известно системе. Починили: идемпотентная
вставка + разовая чистка дублей (Этап 1), обогащение ленты названием/компанией вакансии на
чтении + курсорная пагинация (Этап 2), фронтовая свёртка/группировка ленты по дню (Этап 3), мердж
фактов по теме между разборами вместо дублей формулировок (Этап 4), автосоздание карточки
портфолио по сильному разбору/зафиксированному офферу без статуса «черновик» + возможность
удалить элемент, три формы «Достижений» схлопнуты в одну кнопку с выпадающим меню (Этап 5).
Отдельным заходом той же сессии владелец попросил ещё точечных правок по «Ленте» (окно «3
последних дня / показать ещё → 7», время и раскрывашка группы — слева от иконки, фильтр-чипы по
`kind` убраны, ручное добавление события — рядом чипов прямо в шапке блока вместо формы) — это
уже правки поверх сделанного Этапа 3, не отдельный номерной этап плана.
